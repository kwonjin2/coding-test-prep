## Algorithm

- **Problem**: LeetCode 1, Two Sum, Easy
- **Tags**: 해시, 배열
- **Time**: ~45분 (브루트포스 20분 + 최적화 학습 25분) / 45~60분
- **Status**: 🟡
- **Stuck at**: 최적화 시 해시맵 lookup 패턴을 스스로 떠올리지 못함 (브루트포스는 자가 디버깅으로 해결)
- **Key learning**: 값으로 검색해야 하는 lookup 패턴 → Map 의 key 에 "값", value 에 "인덱스". 검색 방향이 (key, value) 배치를 결정. `has` 체크는 반드시 `set` 보다 먼저 (자기 자신을 짝으로 쓰는 것 방지).
- **Retry**: 2026-05-29

### Code

**브루트포스 (자력 해결)**

```javascript
var twoSum = function (nums, target) {
  for (let i = 0; i < nums.length; i++) {
    for (let j = i + 1; j < nums.length; j++) {
      if (nums[i] + nums[j] === target) return [i, j];
    }
  }
};
```

> 첫 시도에서 `j = 1` 고정 → `[2,5,5,7,11]` 케이스 실패. "나 자신은 짝에서 빼야 한다" 깨닫고 `j = i + 1` 로 수정.

**해시맵 최적화**

```javascript
var twoSum = function (nums, target) {
  const map = new Map();
  for (let i = 0; i < nums.length; i++) {
    const current = nums[i];
    const need = target - current;
    if (map.has(need)) return [map.get(need), i];
    map.set(current, i);
  }
};
```

### 시간/공간 복잡도

- 브루트포스: Time `O(n²)`, Space `O(1)`
- 해시맵: Time `O(n)`, Space `O(n)` (map)

## Reflection

첫날. 알고리즘 감 자체는 살아있는데 **"브루트포스 → 최적화"** 사고가 한 단계에서 멈춤. 풀고 끝내지 말고 "한 번 더 빠르게 만들 수 있나?" 자문하는 습관 필요. 그리고 Map 의 (key, value) 가 임의 배치가 아니라 **검색 방향에 의해 결정** 된다는 원리를 처음으로 명시적으로 이해 — 이게 오늘 가장 값진 수확.
