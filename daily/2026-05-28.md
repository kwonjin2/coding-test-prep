## Algorithm

- **Problem**: LeetCode 20, Valid Parentheses, Easy
- **Tags**: 스택
- **Time**: ~20분 / 45~60분
- **Status**: 🟢
- **Stuck at**: 풀이 자체는 자력 통과. 다만 면접관 후속 — (1) 엣지케이스 think-aloud 가 "빈 문자열" 하나에 그침 (홀수 길이, mismatch 짝 `"(]"`, 닫는 괄호 먼저 들어오는 케이스 누락), (2) `if / if` 연속 분기 자력 인식 X — 지적받고 `else if` 가 맞다고 즉답, (3) **closer→opener 매핑** 이 LC/면접 표준이라는 점 미인지 (본인은 opener→closer 매핑 사용, 동작은 OK).
- **Key learning**: 스택 = "최근 열린 짝 찾기" 도구. 빈 스택일 때 closer 가 들어오는 가드는 본인 코드에서 **JS `undefined` 전파 → `pair[undefined] === closer` 가 항상 false → return false** 로 자연 처리됨 → trace 자력 가능 ✅. 다만 면접 표준은 **closer→opener 매핑 + `stack.pop() !== pair[c]`** 한 줄 비교 (closer 만났을 때 "기대하는 opener" 를 즉시 꺼내쓰는 의도가 더 명확).
- **Retry**: 2026-06-04 (표준 closer→opener 매핑 자력 소환 시험 — opener→closer 가 아닌 closer→opener 가 자력으로 먼저 떠오르는지)

### Code

**자력 풀이 (~20분, 통과)**

```javascript
var isValid = function (s) {
  const stack = [];

  const pair = {
    '(': ')',
    '{': '}',
    '[': ']',
  };

  for (let c of s) {
    if (c === '(' || c === '{' || c === '[') stack.push(c);
    if (c === ')' || c === '}' || c === ']') {
      if (pair[stack[stack.length - 1]] === c) stack.pop();
      else return false;
    }
  }

  return stack.length === 0;
};
```

> 스택 자력 소환 ✅. opener→closer 매핑으로 짝 비교. **다만 `if / if` 연속** — opener 일 때 두 번째 `if` 가 절대 true 가 안 되니 버그는 없으나 의도 측면에서 `else if` 가 정답. opener 판정도 OR 3개라 길어짐.

**면접 표준 패턴 (closer→opener 매핑, 참고용)**

```javascript
var isValid = function (s) {
  const stack = [];
  const pair = { ')': '(', '}': '{', ']': '[' };

  for (const c of s) {
    if (pair[c]) {
      if (stack.pop() !== pair[c]) return false;
    } else {
      stack.push(c);
    }
  }
  return stack.length === 0;
};
```

> 차이는 두 가지:
> - **매핑 방향이 closer→opener** — closer 를 만난 순간 "기대하는 opener" 가 바로 손에 잡힘
> - **`if (pair[c])` 한 줄로 closer 판정** — OR 3개 압축
> - 빈 스택 가드는 본인 코드와 같은 원리: `stack.pop()` 이 `undefined` 면 어떤 opener 와도 안 같음 → false

### 시간/공간 복잡도

- Time: **O(n)** — 문자열 한 번 순회, push/pop/lookup 모두 O(1)
- Space: **O(n)** — worst case 전부 opener (`"((((("`) 면 stack 에 n 개

### 엣지케이스 (다음번엔 자력으로 짚을 것)

- 빈 문자열 `""` → stack 비어있음 → true ✅
- 닫는 괄호 먼저 `")"`, `"]"` → `pair[undefined]` 또는 `stack.pop() === undefined` → false ✅
- 홀수 길이 `"(()"` → 한 쪽 남음 → false ✅ (early return 으로 `if (s.length % 2) return false` 추가 가능)
- mismatch 짝 `"(]"` → 짝 비교 단계에서 false ✅
- 같은 opener 만 `"(("` → loop 끝나도 stack 비안 비음 → false ✅

### Interviewer feedback (Claude)

- ✅ **스택 0회 → 자력 통과 + 20분 ~ 면접 통과 시간 안.** opener→closer 매핑 자체는 본인이 떠올린 첫 회로 — 신규 자료구조 진입 치고 깔끔.
- ✅ **빈 스택 가드 trace 자력 가능.** `pair[stack[stack.length - 1]]` = `pair[undefined]` = `undefined` ≠ closer → false 까지 본인 입으로 정확히 풀어냄. **"운 좋게 통과" 가 아니라 "코드를 안다" 의 분기점**이 이 trace 능력.
- ⚠️ **엣지케이스 think-aloud 빈약.** "빈 문자열" 하나만 짚음 → 실제 코드는 5개 케이스 모두 처리. **본인 코드가 잘 처리하는 케이스조차 입으로 못 짚는 게 면접 감점 포인트** — 5/26 의 "풀이 직후 1초 자문" 의 엣지케이스 버전. 다음 풀이부터 base 통과 직후 "내가 안 짚은 엣지케이스가 뭐 더 있나?" 자문 루틴.
- ⚠️ **`if / if` → `else if`** — 지적받고 즉답 가능. 즉 **모르는 게 아니라 작성 단계에서 의식 X**. think-aloud → 코드 변환에서 5/27 debounce 와 비슷한 갭 (말로는 정확, 활자에서 누락).
- 📝 **closer→opener 매핑은 retry 시 자력 소환 시험.** 동작은 OK 라 🟢 유지, 다만 면접관이 "다른 방식?" 후속 물어오면 즉답 가능해야 가산점.
