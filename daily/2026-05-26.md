- **Tags**: 해시, 배열

- **Status**: 🟢
- **Stuck at**: 풀이 자체는 막힘 없음. 다만 면접관 시점 후속 질문에서 — (1) 공간복잡도 worst case 사고 흔들림 (O(n log n) 이라 답함), (2) early exit 자력 도출 X (힌트 한 번 받고 도출), (3) Set 내부 구조(hash table) 지식 부재.
- **Key learning**: Set 은 "중복 제거" 도구가 아니라 **"O(1) 멤버십 검사 (hash table 기반)" 도구.** 중복 제거는 그 결과로 따라오는 부산물. 그리고 **풀이 직후 "다 넣고 비교 vs 찾으면 종료" 자문 루틴** — 5/25 의 "제약 한 번 더 읽기" 와 같은 계열의 후속 회로.
- **Retry**: -

### Code

**초기 풀이 (자력, 2분)**

```javascript
var containsDuplicate = function (nums) {
  const set = new Set();

  for (let i = 0; i < nums.length; i++) {
    set.add(nums[i]);
  }

  if (set.size === nums.length) return false;
  return true;
};
```

> Set 자력 소환 ✅. 다만 **전부 채운 뒤 size 비교** — early exit 누락.

**최종 풀이 (early exit + dead code 제거)**

```javascript
var containsDuplicate = function (nums) {
  const set = new Set();

  for (let i = 0; i < nums.length; i++) {
    if (set.has(nums[i])) return true;
    set.add(nums[i]);
  }

  return false;
};
```

> for 안에서 `has` → 첫 중복 즉시 return. loop 가 끝까지 돌았다는 건 중복 없다는 뜻이라 뒤는 `return false` 1줄로 충분.

### 시간/공간 복잡도

- Time: **O(n)** — 한 번 순회, `has`/`add` 각각 평균 O(1) (hash table)
- Space: **O(n)** — worst case 전부 unique 면 set 에 n 개. (worst case 기준으로 답하는 게 면접 정답)

> 대안 비교:
> - `Array.includes` 기반: O(n²) — `includes` 자체가 O(n) 선형 스캔
> - 정렬 후 인접 비교: Time O(n log n), Space O(1) (in-place sort 기준)

### Interviewer feedback (Claude)

- ✅ **Set 자력 소환 + 2분 풀이** — Two Sum (5/22) → Anagram (5/25) → 217 의 흐름이 굳어가는 게 보임. "lookup/멤버십 검사 = 해시 자료구조" 회로 정착.
- ⚠️ **복잡도는 worst case 로 곧장 답하기.** "살짝 적을 듯" 같은 평균 사고는 면접에서 감점. 자료구조에 n 개 들어갈 수 있는지 한 번 자문하고 답할 것.
- ⚠️ **"Set = 중복 제거" 는 용도, "Set = O(1) 멤버십 검사 (hash table)" 가 원리.** 면접관이 "왜 빠른가?" 물으면 후자로 답해야 가산점.
- ⚠️ **base solution 작성 단계에서 early exit 자문 루틴 X.** 5/25 의 "제약 한 번 더 읽기" 와 같은 계열의 후속 회로 — 다음 풀이부터 풀이 직후 1초 자문 ("다 넣고 비교 vs 찾으면 종료") 습관화.
- 📝 dead code 제거 (`if (set.size === nums.length) return false; return true;` → `return false`) 는 한 번 짚어주니 즉시 도출. 다음엔 작성 단계에서 도달 가능성 체크하는 시야.
