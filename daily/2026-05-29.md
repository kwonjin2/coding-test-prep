  2. **엣지케이스 첫답 빗나감** — "target 이 배열만으론 안 나오는 경우" 로 답. 사실 LC 문제는 "Exactly one solution exists" 보장이라 발생 X. 진짜 짚어야 할 건 `[3,3], target=6` 같이 **같은 값 두 번 사용** 케이스. 힌트 한 번 받고 자력 도출 ✅.
  3. **has → set 순서 이유 첫답 빗나감** — "불필요한 숫자도 같이 들어감" 까지만. 진짜 결과 ("자기 자신과 짝 매칭, 같은 인덱스 두 번 반환") 는 뒤집은 코드 trace 유도 후 자력 도출 ✅.
  4. **think-aloud 누락 — 무의식적 패턴.** 본인이 직접 인정. 5/27 debounce → 5/28 Valid Parentheses → 5/29 Two Sum 3연속 같은 갭.
- **Key learning**: has → set 순서의 진짜 이유는 **"자기 자신과 짝 매칭 방지"** — `set` 먼저 하면 `current` 가 map 에 들어가있는 상태에서 `need == current` 인 경우 `[i, i]` (같은 인덱스 두 번) 가 반환됨. `[3,3], target=6` 같은 케이스에서 trace 하면 즉시 드러남. has → set 순서는 단순 관습이 아니라 **"map 에는 i 이전의 원소만 있다"** 라는 invariant 를 강제하는 장치.

### Code

**자력 풀이 (~5분, 통과)**

```javascript
var twoSum = function (nums, target) {
  const map = new Map();

  for (let i = 0; i < nums.length; i++) {
    const current = nums[i];
    const need = target - current;
    if (map.has(need)) return [map.get(need), i];
    map.set(current, i);
  }
};
```

> 한 번 순회 + need 미리 계산 + has → set 순서 ✅. 변수명 `current`, `need` 의미 명확. 5/22 대비 흐름 자동화됨.

### 시간/공간 복잡도

- Time: **O(n)** — 한 번 순회, `has`/`get`/`set` 각각 평균 O(1)
- Space: **O(n)** — worst case (정답이 마지막 두 원소) 까지 map 에 n-1 개 누적

### 엣지케이스 (다음번엔 자력으로 짚을 것)

- **같은 값 두 번 사용**: `[3,3], target=6` → i=0 에서 has(3) false → set([3,0]), i=1 에서 has(3) true → [0,1] ✅
- 음수/0 포함: 영향 없음 (산술만 따져서 OK)
- 정답이 첫 두 원소 vs 마지막 두 원소: 첫 두 원소면 i=1 에서 조기 종료, 마지막 두 원소면 끝까지 순회 (worst case)
- **답 없는 경우는 LC constraint 상 발생 X** — 방어적 코드 (`return []`) 추가는 면접 가산점이나 필수는 아님

### `has` → `set` 순서 trace (자력 도출 ✅)

뒤집은 버전:

```javascript
for (let i = 0; i < nums.length; i++) {
  map.set(current, i);                          // ← 먼저 넣음
  if (map.has(need)) return [map.get(need), i]; // ← 검사
}
```

`nums=[3,2,4], target=6`, `i=0` 일 때:
- `current = 3`, `need = 3`
- `set(3, 0)` → map: `{3 → 0}`
- `has(3)` → true → `[0, 0]` 반환 → **같은 인덱스 두 번 = 자기 자신과 짝.** 오답.

올바른 순서 (has → set):
- `i=0`: has(3) false (map 비어있음) → set(3, 0)
- `i=1`: current=2, need=4, has(4) false → set(2, 1)
- `i=2`: current=4, need=2, has(2) true → [1, 2] ✅

즉 has → set 순서는 **"map 에는 항상 i 이전 원소만"** invariant 를 강제.
